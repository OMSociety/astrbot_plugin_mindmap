# 思维导图 / 时间线 / 表格 / 流程图绘制（astrbot_plugin_mindmap）

> 不要向用户说明你正在读取规范、正在使用技能或即将调用工具；不描述过程，只交付最终结果。

插件提供三个 LLM 工具，均把输入渲染为 PNG 图片：

- `draw_mindmap(outline, layout, theme, send)`：思维导图或时间线。
- `draw_table(markdown, title, theme, send)`：标准 Markdown 表格。
- `draw_flowchart(spec, direction, theme, send)`：基础流程图。

## 何时画、画哪种

| 场景 | 工具与布局 |
|---|---|
| 知识结构梳理、概念体系、分类对比 | `draw_mindmap`，`layout="tree"`，根在左向右展开 |
| 历史脉络、发展线索、事件先后 | `draw_mindmap`，`layout="timeline"`，竖轴节点左右交替 |
| 大纲类型不确定 | `draw_mindmap`，`layout="auto"`，按叶子节点是否多为日期判定 |
| 行列对比、结构化清单 | `draw_table` |
| 有明确先后、条件分支或汇合的处理过程 | `draw_flowchart` |

思维导图优先显式传 `tree` 或 `timeline`，`auto` 只是兜底。材料不构成单向、无歧义的流程时，改用思维导图或表格，不猜测流程关系。

## 配色

三个工具的 `theme` 参数接受相同形式：

- 内置主题名：朱砂（默认）、靛蓝、松绿、琥珀、墨灰、黛紫。
- `#RRGGBB` 自定义主色：其余色阶由主色自动派生。

留空即默认主题。只有用户点名要某种色调、或主题内容气质与默认红明显不合时才换（如庄重的悼念/制度类内容可用墨灰，科技与法学可用靛蓝）；不要为了「好看」每张图换一个颜色，同一场对话里保持一致的配色。

## 思维导图与时间线大纲

两种等价写法（可混用），用 `#` 标题或 `-` 列表缩进表示层级：

```markdown
# 主题
## 分支一
- 要点甲
  - 细节
## 分支二
- 要点乙
```

或：

```markdown
主题
- 分支一
  - 要点甲
- 分支二
  - 要点乙
```

时间线节点写成「时间标签: 描述」，标签可省略（按序排列）：

```markdown
# 法国大革命至巴黎公社的思想脉络
- 1789: 三级会议召开，旧制度合法性崩塌
- 1789–1791: 《人权与公民权宣言》颁布
- 空想社会主义思潮兴起
```

软建议（超出后图仍可生成，但宜主动精简）：

- 层级 ≤ 4 层。
- 每个分支 ≤ 6 个子节点。
- 总节点 ≤ 60。
- 单节点 ≤ 40 字（一句话说清一个要点）。

硬上限（超限拒绝生成，会收到固定短语提示）：

- 总节点 > 200，或
- 单节点 > 200 字，或
- 层级 > 8。

超限处理：合并同类节点、把长节点拆成父子两级、或拆成多张图分别绘制。不要静默裁剪内容。

## 表格输入

`markdown` 只传标准 Markdown 表格，包含表头、分隔行与数据行；表格标题单独传给 `title`，不写进 `markdown`。标题最多 80 字，超宽自动折行；单元格使用纯文本。

```text
draw_table(markdown="| 批判 | 核心问题 |\n| --- | --- |\n| 纯粹理性批判 | 我能够知道什么？ |\n| 实践理性批判 | 我应当做什么？ |", title="康德的批判哲学", theme="朱砂", send=True)
```

限制：最多 8 列、50 个数据行，每个单元格最多 200 字；不支持合并单元格或富文本。超限时拆分表格，不静默省略行列或截断单元格。

## 流程图输入

`spec` 由可选标题、节点声明和有向边组成。首行可写 `# 标题`（最多 80 字，超宽自动折行）；没有独立标题参数。每个节点单独一行，格式为 `节点ID [类型] 节点文字`：

- 节点 ID 必须以 ASCII 字母开头，之后只含 ASCII 字母、数字、`_` 或 `-`。
- 类型为 `start`、`process`、`decision`、`end`，可省略，缺省为 `process`。
- 边写成 `起点 -> 终点`；分支标签加在英文或中文冒号后，如 `check -> process: 是` 或 `check -> process：是`。
- 支持顺序、分支和汇合；唯一入口声明为 `[start]`，各末端用 `[end]` 收尾；中间节点不能悬空在末端。
- 默认 `direction="vertical"`，需要横向时传 `horizontal`。
- 最多 30 个节点。

```text
draw_flowchart(spec="# 材料处理\nstart [start] 收到材料\ncheck [decision] 材料完整？\nprocess [process] 提取概念\nsupplement [process] 补充材料\ndone [end] 形成体系\nstart -> check\ncheck -> process: 是\ncheck -> supplement: 否\nprocess -> done\nsupplement -> done", direction="vertical", theme="朱砂", send=True)
```

回环、跨层连线、不可达节点和歧义输入会被拒绝。遇到拒绝时，补充明确的节点或边、删除不合法关系，或拆成多个单向子流程；不要自行猜测用户未表达的连接关系。

## 发送纪律

图片必须由上述三个工具之一发送（`send=True` 默认行为），不要改用其他发送类工具（如 `send_message_to_user`）转发图片。那些工具走主动消息通道，部分平台（如 QQ 官方机器人）默认无主动发消息权限，会直接被拒（报「主动消息失败，无权限」）。这些工具把图片挂在当前用户消息的被动回复上发送，不受此限。

## 文档嵌入

任一工具传 `send=False` 时只渲染、不发图，并返回文件路径：

```text
draw_mindmap(outline=..., layout="tree", send=False)
draw_table(markdown=..., title=..., send=False)
draw_flowchart(spec=..., direction="vertical", send=False)
```

用文件工具读取该路径即可嵌入 docx 或做二次加工，不要把路径念给用户。

发图成功时返回 `[图片已发送]` 事件标记——这是系统状态，不复述、不转述，直接顺着图表继续讲解。

## 学术准确性要求

- 图表文字必须忠于原始材料，不臆造、不静默删改；超长内容拆节点、行列或子流程，而非截断。
- 时间线的时间标签须与史料一致，不确定的年份标注「约」。
- 大纲结构应反映学界公认的分类框架；有争议处按用户给定的口径组织。
- 表格的表头、单位与数据对应关系必须明确；流程图的条件标签与分支方向必须能由材料直接支持。

## 表达与发送纪律

- 图片必须由对应绘图工具发送，不使用其他消息工具转发。
- 用户表达画图意图后直接调用工具；理论讲解中图表有帮助时也主动调用，无需等待明确要求。
- 调用工具前后不要解释操作过程，不说“我来调用工具”“正在生成图片”“图发你了”“已发送”等元话语。
- 不要为工具调用写单独的预告或交付句。把图片放在相关理论内容之后，再用自然语言承接图意。
- 图片前后的文字应是一段完整讲解的自然组成部分，而不是使用说明或工具回执。
- 失败后平实说明内容与问题，不描述内部工具或渲染过程。

## 常见失败短语与对策

| 短语 | 对策 |
|---|---|
| 大纲为空 | 传入非空大纲文本 |
| 第 N 行：列表缩进 N 个空格不是 2 的倍数 | 把该行缩进改成偶数空格（2/4/6…）或改用 tab |
| timeline 布局仅支持一层事件节点 | 改用 tree 布局，或把深层条目并入父节点描述 |
| 节点数/单节点字数超上限 | 按大纲规模建议精简后重试 |
| 表格列数、数据行数或单元格字数超上限 | 拆成多张小表或缩短单元格文字 |
| 流程图存在回环、跨层连线、不可达节点或歧义 | 明确流程关系，或拆成多个单向子流程 |
